What changed in the save system

Three versions side by side. v1 is what the shipped game uses. "v2 first" is steps 1 and 2. "v2 now" is after your review. How the system works today is in save-system.html.

v1

Tag save-system-v1. The shipped game stays on it.

  • Needed a SaveManager in the scene.
  • Data arrived late, after Start.
  • Only MonoBehaviours could save.
  • Listing and deleting game profiles didn't work.

v2 first

Commits T0 to T13.

  • Safe saving, with a backup of every file.
  • Data arrives before Start.
  • No manager. Plain classes and assets can save.
  • Main class renamed to SaveSystem. Load events removed.

v2 now

Commits A2 to B9.

  • Old names back: SaveActions, SaveEventBus.
  • Save files are classes, so typos don't compile.
  • Load events back, game profile objects, optional backups.
  • SaveStorage for tools. A Create Config menu item.

The main class

v1
SaveActions.SaveAll();
v2 first
SaveSystem.SaveAll();
// Clashed with the namespace
// AbstractPixel.SaveSystem.
v2 now
SaveActions.SaveAll();

The v1 name is back. It matches SettingsActions and has no clash.

Choosing a save file

v1
[Savable(SaveCategory.Game)]
public class Health : MonoBehaviour,
    ISavable<int> { … }
v2 first
[Savable(SaveCategory.Game)]
public class Health : MonoBehaviour,
    ISavable<int> { … }
// Same as v1.
v2 now
public class Chest : MonoBehaviour,
    ISavable<bool, SaveFiles.Scene> { … }
// No attribute, no enum.

The config's save file list defines the files. The editor writes SaveFiles.cs from it.

Saving and loading

v1
SaveActions.SaveDataOf(SaveCategory.Settings);
SaveActions.LoadAll();
v2 first
SaveSystem.Save("Settings");
// No load call.
v2 now
SaveActions.Save<SaveFiles.Settings>();
SaveActions.Reload<SaveFiles.Settings>();

Saving one file takes a class, not a string.

    .SaveFile(json, path);

// Safe, but needed five objects:

What I checked

  • 178 EditMode and 13 PlayMode tests pass.
  • Every library module compiles.
  • I played all six samples and a Settings scene in the Editor. No errors.
  • I checked the Unity calls against the Unity 6 docs. The tests have not run on Unity 6.

Choices I made

  • A Scene file's load event waits one frame, so every script in the scene has started.
  • Unticking Backup deletes the old backup on the next save.
  • Samples bring their own save file classes, because they can't see your SaveFiles.cs.
  • I kept the main page and rewrote it as the guide, instead of deleting it.
