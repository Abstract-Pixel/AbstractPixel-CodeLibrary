Layer 1 · every script

Mark it, and it saves

Mark the fields you want saved

planned · phase C
public class Health : MonoBehaviour
{
    [Save] int current;
    [Save] bool isPoisoned;

    void Awake() { current = 100; }   // new-game value
}

That's the whole script. The data goes to the GameProfile save file of the open game profile. The editor adds a Savable Bridge to the GameObject for you.

Saves numbers, text, true/false, enums, Vector2, Vector3, Quaternion, Color, lists, arrays, dictionaries and your own [Serializable] classes.
Can't save a reference to a GameObject, script or asset. Save its save ID instead. You get a clear error if you try.

The one timing rule

built

The save system puts saved values back right after every Awake and before any Start. So Awake sets new-game values, and Start only reads.

Right: new-game value in Awake

void Awake() { current = 100; }
void Start() { healthBar.Show(current); }
Awake100new game
Restore37saved value
Start37bar shows 37

Wrong: new-game value in Start

void Start()
{
    current = 100;   // overwrites the save
    healthBar.Show(current);
}
Awake0
Restore37
Start37 100save lost

Saving

after review
SaveActions.SaveAll();                      // every save file that changed
SaveActions.Save<SaveFiles.Ghosts>();        // one save file

There is no Load call. An object gets its data as soon as both the object and its data exist. Designers can save from a button with the MonoSaveActions component, which shows the save files as a dropdown.

Game profiles and slots

after reviewplanned · phase B

You never type a name or an ID to create or find a game profile. Each one has a slot number that never changes.

// Create. The name comes from the config.
GameProfile profile = SaveActions.GameProfiles.CreateNew();
// "Game Profile 1"

// Only if you want your own name:
SaveActions.GameProfiles.CreateNew("Hard run");

profile.Open();

// Find one
GameProfile now   = SaveActions.GameProfiles.Current;
GameProfile slot2 = SaveActions.GameProfiles.Get(2);

foreach (GameProfile p in SaveActions.GameProfiles.All)
    ShowSlot(p.SlotNumber, p.DisplayName, p.Playtime);

slot2.Delete();

void OnEnable()
{
    SaveEventBus.OnLoadAllCompleted += CheckAchievements;
    SaveEventBus.OnLoadCompleted += file =>
    {
        if (file == typeof(SaveFiles.Ghosts)) ShowBestGhost();
    };
}
// Also: OnSaveCompleted(file), OnSaveAllCompleted

Sticky means you can't be too late

If your script subscribes after the data already loaded, the handler runs right away. So it doesn't matter whether your script wakes up before or after the save system. No execution order tricks.

loaded at 0.01 s…you subscribe at 2 s→called at once

Save IDs you never have to remember

after reviewplanned · phase C

A save ID is the name of one object's data inside a save file. The same object must get the same ID next session, or it won't find its data. Pick the first row that fits:

Only one of it exists
Inventory, Leaderboard, Settings

SaveActions.Register(this);

No ID. The class name is the ID. A second one without an ID gives a clear error.

Placed in a scene
a chest, a door, an NPC

Nothing to do. The Savable Bridge has an ID already. Its inspector gets a Copy save ID button for when you need it.

Several of one plain class
one per level, one per car

SaveActions.Register(this, level.name);

Use something the object already has that stays the same: a level name, a list index, an asset's name.

Spawned from a prefab
enemies at spawn points

goblin.SetSaveId(spawnPoint.name);

See below.

Come and go at random
dropped loot, bullets

Don't save each one. The spawner saves one list of what exists, and spawns them again next session.

Reading and writing a file directly

after reviewplanned · phase B

For editor tools and debug buttons that touch a save file itself, like clearing leaderboard runs. The config is the source of truth: folder, debug folder, extension, location and backup all come from it.

v1 · 5 lines

SavePathGenerator.Initialize(config);
var def = config.GetCategoryDefinition(
    SaveCategory.Settings);
string path = SavePathGenerator.GetPath(def, id);
var storage = new FileDataStorageService();
storage.SaveFile(json, path);

Short, but you had to find the config, and it broke if nothing set it up first.

Steps 1 and 2 · 6 harder lines

var storage = new DiskStorageService(
    useDebugFolder: true, FileExtension.json);
var paths = new SavePathGenerator();
string key = paths.GetSaveFileKey("Settings",
    SaveLocation.Global, null, null);
var store = new SaveFileStore(storage, new JsonSerializer());
store.Write(key, data);

Repeats what the config already says.

After review · 1 line

SaveStorage.WriteText<SaveFiles.Settings>(json);

Works in play mode and in editor tools. Safe write, backup if the file has one.

SaveStorage.ReadText<SaveFiles.Settings>(out string json);                  // a Global file
SaveStorage.ReadText<SaveFiles.GameProfile>(out string json);               // the open game profile
SaveStorage.ReadText<SaveFiles.GameProfile>(profile, out string json);      // any game profile
SaveStorage.ReadText<SaveFiles.Scene>(profile, "Forest", out string json);  // one scene
SaveStorage.Delete<SaveFiles.Settings>();
string path = SaveStorage.GetFilePath<SaveFiles.Settings>();             // for "Show in Explorer"
foreach (GameProfile profile in SaveStorage.GameProfiles) { ... }       // in edit mode too

Reload and forget

after reviewplanned · phase B
SaveActions.Reload<SaveFiles.Input>();   // read this file from disk again, restore every object in it
SaveActions.Forget(coin);                  // drop this object's data on purpose, like a picked-up coin

Reload is for undoing unsaved changes, like "reset bindings to what was saved". Loading normally stays automatic.

Backups, per save file

after reviewplanned · phase B

You tick Backup on the save files that need one. What's worth it depends on the game: maybe a big GameProfile file, maybe tiny Settings. Each file keeps exactly one backup.

Every save of a file with Backup ticked

current good filecopied toBackups/…replaces the old backup
new datawritten safely as the file

If a file is corrupt next launch, its backup loads and the console says so. A file without Backup logs one error instead.

Game profile manifests are always backed up. They're tiny, and losing one hides a whole slot.

Decisions

Decided in the review

  • Merge main first. ProjectRallyShift stays on v1 for good.
  • SaveActions and SaveEventBus.
  • Save files are classes, generated from the config list.
  • Sticky load and save events, per file and for all.
  • Reload<TFile>() for one file. No public ReloadAll.
  • Game profiles: default name from the config, fixed slot numbers, a handle instead of an ID.
  • Save IDs: class name for one-of-a-kind, bridge ID with a copy button, SetSaveId for spawned copies, Forget takes the object.
  • SaveStorage: one line, the config fills in the rest. Storage parts become internal.
  • Config in Resources, made by a Create Config menu item. Closes #18.
  • Backups: a checkbox per save file, in their own folder.
  • One phase per session, checked in the running Editor.

Confirmed by you after the review

1 · Library modules bring their own save file

Settings ships a SettingsSaveFile class, and the config list shows it by itself. The library can't see your game's generated SaveFiles.cs, so Settings can't use SaveFiles.Settings.

2 · Where the Backups folder sits

SaveFiles/Backups/, mirroring everything, rather than inside GameProfiles/. One place also covers Global files.

3 · New save files start with Backup ticked

Safer by default. You untick what doesn't need one.

4 · A spawned copy without an ID isn't saved

It warns instead of numbering copies by spawn order, which silently swaps data if the order changes.
