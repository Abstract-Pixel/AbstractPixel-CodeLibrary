Save System

How to save data in a game with this library. The parts you use most come first. Words in bold are in the glossary, Modules/SaveSystem/GLOSSARY.md.

What works today

  • DoneSafe saving to disk, with optional backups.
  • DoneScripts get their saved data before Start. No manager in the scene.
  • DoneSave files as classes, events, game profiles, SaveStorage, a Create Config menu item.
  • DoneFive built-in save files, save IDs you never type, Forget that keeps scene objects gone, new-game values for a new game profile.
  • NextThe last bug fixes, then a cleanup that removes dead and repeated code and hides the parts game code doesn't need.
  • Then[Save] fields, checks that stop the wrong setup before play mode, renames that keep data, autosave, and designer tools.

211 EditMode and 17 PlayMode tests pass (commit 15915d7). Works on Unity 6 and Unity 7. The full plan is in save-system-v2-plan.html, the roadmap.

The ladder

read once

The save system is built in four levels. Most of a game only needs the first two. Each level is found from the one below it: the doc comment on each call names the next step, and every error says how to fix it.

LevelWhoWhat you useState
0. No codeDesignersMonoSaveActions on a button, the config's save settings. Coming: ready-made savers (Save Transform, Save Active State, Save Destroyed), autosave every few minutes, UnityEvents for "loaded" and "saved", a save slot screen.Part built
1. Daily codeDevelopersToday: ISavable<TData>, SaveActions.Register(this), SaveActions.Forget, SaveActions.SaveAll(). Coming: [Save] on a field, which replaces the interface for most scripts.Built; [Save] next
2. ChoicesDevelopersPick a save file, game profiles and slots, load events. Coming: ISaveIn<TFile>, IOnRestored, SetSaveId for spawned copies.Part built
3. Full controlTools, unusual casesISavable<TData> for data that isn't plain fields, SaveStorage for whole files, custom game profile fields, [SaveFileDefaults] for library modules.Built
The wrong way should be hard. Once [Save] fields arrive, a mistake the editor can see stops play mode and builds, with one error naming the fix. For example, [Save] on a GameObject field. Renaming a field, class, save file row or GameObject never loses saved data.

Save a script

every saved script

Today a saved script has two methods. [Save] fields come next and will replace them for most scripts. CaptureData returns what to save. RestoreData puts it back. The editor adds a Savable Bridge to the GameObject, which connects the script to the save system.

A saved MonoBehaviour
public class Health : MonoBehaviour, ISavable<int>
{
    public int Current { get; private set; }

    void Awake() { Current = 100; }   // new-game value

    public int CaptureData() => Current;
    public void RestoreData(int loadedData) => Current = loadedData;
}

The save system restores data after every Awake and before any Start. So any script can read the saved value in Start. Objects spawned later get their data the same way.

Set new-game values in Awake. A value set in Start overwrites the saved one.

When a script registers, the save system keeps a copy of its values before restoring anything. Those are its new-game values. If the player opens a game profile that has no data for that script, for example a new game while a DontDestroyOnLoad manager stays alive, the script gets those values back instead of keeping the last game profile's.

Choose the save file

ISavable<TData> saves into the built-in GameProfile file. To use another file, add its class as a second type.

Naming a save file
public class VolumeSetting : MonoBehaviour, ISavable<int, SaveFiles.Settings> { … }
public class Chest : MonoBehaviour, ISavable<bool, SaveFiles.Scene> { … }

A typo in the class name won't compile.

Save and load

every game

Game code calls SaveActions. There is no Load call. A script gets its data when it registers.

SaveActions
SaveActions.SaveAll();                       // write every file that changed
SaveActions.Save<SaveFiles.Settings>();      // write one file
SaveActions.Reload<SaveFiles.Settings>();    // read one file from disk again
SaveActions.Forget(coin.gameObject);         // a picked-up coin stays gone
  • Saving keeps the data of objects that aren't loaded, such as a boss in another scene.
  • When an object is destroyed, the save system keeps its last values for the next save.
  • For buttons and UnityEvents, add MonoSaveActions. It has SaveAll() and SaveChosenFile(). You pick the file in its inspector.
  • The config can save when the game quits or loses focus. Both are off by default. Saving when a scene unloads and every few minutes is coming.

Set it up

once per project

Click Tools > External Project Tools > Save System > Create Config. That's it. Nothing goes in a scene.

The menu item creates Assets/Resources/SaveSystemConfig.asset. The save system reads it before the first scene loads.

Config fieldWhat it does
Use Debug PathSaves to DebugSaveFiles/ next to Assets/, so you can open the files.
Startup PolicyAutoSetUp opens the last game profile at startup. Manual waits for your save slot screen.
Default Game Profile NameNew game profiles get this name plus a number, such as "Game Profile 2".
Game Profile Guid LengthLength of a game profile's folder name.
Primary File ExtensionThe file type, such as json.
Save On Quit, Save On Focus LossAutosave. Off by default.
Game Save Files Script PathWhere the editor writes GameSaveFiles.cs, the classes for your own save files.
Save file listOne row per save file. See the next part.
With no config, you get one error that names the menu item. Save calls then do nothing, and the game keeps running.

Save files

once, then rarely

The config has a save file list. Each row is one file, with a name, a save location and a Backup box.

Every game has five built-in save files. Their classes ship with the library, so library modules and game code can both use them. You can't remove or rename them; only their Backup box changes.

Built-in save fileSave locationFor
SaveFiles.GameProfileGame ProfileOne playthrough. The default when a script names no file.
SaveFiles.SceneSceneOne scene in one playthrough.
SaveFiles.SettingsGlobalVolume, graphics. The Settings module uses it.
SaveFiles.InputGlobalInput bindings.
SaveFiles.AchievementsGlobalAchievements.

Add rows for your own game save files, such as Ghosts. The editor writes their classes into GameSaveFiles.cs.

GameSaveFiles.cs (written by the editor)
public static class GameSaveFiles
{
    public sealed class Ghosts : ISaveFile { }     // a row you added
}

SaveActions.Save<SaveFiles.Settings>();        // a built-in save file
SaveActions.Save<GameSaveFiles.Ghosts>();       // your own
  • Renaming a row keeps its old data. Each row remembers the name it was saved under.
  • Two rows that would share a file on disk, or make the same class name, get a warning in the config. GameSaveFiles.cs isn't written until you fix it. (This check is being finished in the next run.)
  • A library module uses a built-in save file when one fits. If none does, it brings its own class, and the editor adds its row for you.
A module's own save file
[SaveFileDefaults("Ghost Runs", SaveLocation.GameProfile)]
public sealed class GhostRunsSaveFile : ISaveFile { }

Save locations

most games

Each save file lives in one of three places. The row in the config decides which.

Save locationHoldsExample
GlobalData every game profile sharesSettings, input bindings, achievements
GameProfileOne playthroughCoins, inventory
SceneOne scene in one playthroughOpen chests in the Forest

Switching game profiles keeps Global data and swaps the rest. An object in an additive scene saves into its own scene's file.

Game profiles

most games

A game profile is one playthrough. You hold a GameProfile object and call its methods. Each one has a slot number that never changes.

A save slot screen
GameProfile created = SaveActions.GameProfiles.CreateNew();   // named "Game Profile 3"
GameProfile slot = SaveActions.GameProfiles.Get(2);           // by slot number
slot.Open();
SceneManager.LoadScene(SceneManager.GetActiveScene().name);   // reload after opening

foreach (GameProfile profile in SaveActions.GameProfiles.All)
{
    Debug.Log($"{profile.SlotNumber} {profile.DisplayName} {profile.LastSaved}");
}

slot.Rename("Hard mode");
slot.Delete();                                 // deletes its files and backups
GameProfile open = SaveActions.GameProfiles.Current;   // null if none is open
  • Each save updates the open profile's last saved time, last scene and playtime. Put your own details, such as difficulty, in profile.Custom.
  • Reload your scenes after opening another game profile.
  • Objects that stay alive across the switch get their saved data from the new game profile, or their new-game values if it has none.
  • Coming: SaveActions.GameProfiles.LastOpened and Count, for a Continue button that greys out when there are no saves.

Plain C# classes

often

Any class can save. It registers itself, and needs no save ID.

A plain class
public class Inventory : ISavable<InventoryData>
{
    public List<string> Items { get; private set; }

    public Inventory()
    {
        Items = new List<string> { "Wooden Sword" };
        SaveActions.Register(this);   // last line. Save ID "Inventory"
    }

    public InventoryData CaptureData() => new InventoryData { Items = new List<string>(Items) };
    public void RestoreData(InventoryData loadedData) => Items = new List<string>(loadedData.Items);
}

void OnDestroy() => SaveActions.Unregister(inventory);   // in the owner

Register on the last line, because saved data may arrive inside that call.

  • The class name is the save ID. A second live instance gets "Inventory 2", then "Inventory 3", in the order they register.
  • If that order can change between runs, numbered instances would swap data. Give each one a custom save ID: SaveActions.Register(this, level.name).
  • Renaming the class changes its save ID, so old saves lose its data. Until the rename-safe attribute arrives, give a class you might rename a custom save ID.

Events

sometimes

SaveEventBus tells scripts when data has loaded or saved. Load events are sticky. A script that subscribes late still gets called.

SaveEventBus
SaveEventBus.OnLoadCompleted += file =>          // one file loaded
{
    if (file == typeof(SaveFiles.Ghosts)) { ShowGhosts(); }
};
SaveEventBus.OnLoadAllCompleted += Refresh;       // everything loaded
SaveEventBus.OnGameProfileOpened += profile => { };
SaveEventBus.OnSaveCompleted += file => { };      // one file saved
SaveEventBus.OnSaveAllCompleted += ShowSavedIcon;
  • A load event comes after every object in that file has its data.
  • A Scene file sends its load event once per scene, one frame after the scene starts.
  • OnLoadAllCompleted runs each time a game profile opens.
  • If one handler throws, the others still run.
  • Coming: SaveEventBus.AddLoadListener<GameSaveFiles.Ghosts>(ShowGhosts), which needs no type check, and OnSaveFailed, so the game can tell the player a save didn't work.

Forget data

sometimes

Use it for a coin that was picked up. Pass the object, its script or its GameObject.

SaveActions.Forget
void OnPickedUp()
{
    SaveActions.Forget(gameObject);   // stays gone after a reload
    Destroy(gameObject);
}
  • An object placed in a scene comes back every time the scene loads, so removing its data isn't enough. Forget writes a gone marker instead. Next time the scene loads, the object turns itself off in its bridge's Start, before its other scripts start. Their Awake has already run.
  • A plain class (and, later, a spawned copy) has its data removed. Nothing brings it back except your own code.
  • A gone marker belongs to one game profile. A new game has the coin again.
  • With no game profile open, Forget of game profile data logs one error and changes nothing.

ScriptableObjects

sometimes

An asset registers itself, like a plain class. This becomes automatic in a later step.

A saved asset
public class GameProgress : ScriptableObject, ISavable<GameProgressData>
{
    public int LevelsCompleted;

    void OnEnable()  => RegisterWithSaveSystem();
    void OnDisable() => SaveActions.Unregister(this);

    // A scene script calls this again in Awake, in case the asset loaded too early.
    public void RegisterWithSaveSystem() => SaveActions.Register(this, "game-progress");

    public GameProgressData CaptureData() => new GameProgressData { LevelsCompleted = LevelsCompleted };
    public void RestoreData(GameProgressData loadedData) => LevelsCompleted = loadedData.LevelsCompleted;
}

SaveStorage

editor tools, debug buttons

SaveStorage reads or writes a whole save file as JSON in one line. The config tells it where the file is. It works in play mode and edit mode.

SaveStorage
SaveStorage.ReadText<SaveFiles.Settings>(out string json);                 // Global file
SaveStorage.ReadText<SaveFiles.GameProfile>(out string json);              // open game profile
SaveStorage.ReadText<SaveFiles.GameProfile>(profile, out string json);     // any game profile
SaveStorage.ReadText<SaveFiles.Scene>(forestScene, out string json);      // one scene, open game profile
SaveStorage.ReadText<SaveFiles.Scene>(forestScene, profile, out string json);
SaveStorage.WriteText<SaveFiles.Settings>(json);
SaveStorage.Delete<SaveFiles.Settings>();                                  // the backup too
string path = SaveStorage.GetFilePath<SaveFiles.Settings>();
foreach (GameProfile profile in SaveStorage.GameProfiles) { }
  • forestScene is a SceneField from AbstractPixel.Core, picked in the inspector. A Scene file always needs one, so the save system never guesses the scene.
  • ReadText, WriteText, Delete and GetFilePath all take the same four shapes: nothing, a game profile, a scene, or both.
  • A wrong combination, such as a scene for a Global file, logs one error that shows the right call, and does nothing.
  • In play mode, WriteText and Delete update the running game too. You don't need to call Reload.

Files on disk

while debugging

A save never leaves a half-written file. The save system writes a temporary file first, then swaps it in. Backups sit in their own folder with the same layout.

Folders
SaveFiles/
  Global/
    Settings.json
    SaveSystemMetaData.json      which game profile to open at startup
  GameProfiles/
    a1b2c3/
      GameProfileManifest.json   what the slot screen shows
      GameProfile.json
      Scenes/Forest/Scene.json
  Backups/                       same layout, last good copy of each file
    Global/Settings.json
    GameProfiles/a1b2c3/GameProfile.json
One save file
{
  "FormatVersion": 2,
  "Version": "1.0",
  "Timestamp": "2026-11-13T04:12:08.0000000Z",
  "ProfileID": "a1b2c3",
  "FileName": "GameProfile",
  "Entries": {
    "5eecb91f-…/27062df3-…": {
      "name": "Assets/Scenes/Level.unity/Player/Health",
      "data": 40
    },
    "9b1c44d0-…/a7e2f310-…": {
      "name": "Assets/Scenes/Level.unity/Coin (3)/Coin",
      "gone": true                 a gone marker: this coin was picked up
    }
  }
}
  • The save system matches entries by save ID. The name is only for people.
  • With Backup ticked, a broken file loads its backup, with a warning.
  • With Backup unticked, a broken file logs one error and loads nothing.
  • The game profile manifest and the metadata file always have backups.
