Save System

How the save system works, from the one line every saved script writes down to the storage underneath. The parts you use in almost every project come first; the internals come last. Words in bold are from the glossary, Modules/SaveSystem/GLOSSARY.md.

What is built

  • DoneSafe storage. Atomic writes, optional backups, three save locations, game profiles.
  • DoneThe core. Restore after Awake and before Start, no manager in the scene, plain C# classes and ScriptableObjects can save.
  • DoneReview fixes. Save files as classes, SaveStorage, sticky load events, GameProfile handles, the Create Config menu item.
  • NextSaved objects. [Save] fields, IOnRestored, save IDs you never type, SetSaveId for spawned copies.
  • LaterScriptableObjects registered automatically, bridges added while editing, the Save System window, ready-made savers.

Tests: 178 EditMode and 13 PlayMode, all passing. Works on Unity 6 and Unity 7.

Saving a script

every saved script

A saved script says what to save and how to put it back. The Savable Bridge component on the same GameObject connects it to the save system; the editor adds the bridge for you and gives it a save ID.

A saved MonoBehaviour
public class Health : MonoBehaviour, ISavable<int>
{
    public int Current { get; private set; }

    // New-game values go in Awake.
    void Awake() { Current = 100; }

    public int CaptureData() => Current;
    public void RestoreData(int loadedData) => Current = loadedData;
}

// Any script can read the saved value in Start:
void Start() { shownHealth = health.Current; }   // already restored

The save system restores right after every Awake and before any Start. It restores an object as soon as both the object and its data exist, whichever comes second, so an object spawned later, or disabled and enabled again, gets its data back the same way.

Set new-game values in Awake, never in Start. If Start assigns a saved value, it overwrites the value the save system just restored.

Picking the save file

ISavable<TData> saves into the built-in GameProfile save file. To save somewhere else, name the save file class as a second type:

Naming a save file
public class VolumeSetting : MonoBehaviour, ISavable<int, SaveFiles.Settings>  // shared by every game profile
public class Chest : MonoBehaviour, ISavable<bool, SaveFiles.Scene>            // one file per scene

A typo in a save file class doesn't compile. Where each save file lives is set in the config, not in the script (see Save files).

Saving and loading

every game

SaveActions is the one class game code calls. There is no Load call: objects restore when they register, and opening a game profile restores everything registered before it.

SaveActions
SaveActions.SaveAll();                       // writes every save file that changed
SaveActions.Save<SaveFiles.Settings>();      // one save file
SaveActions.Reload<SaveFiles.Settings>();    // read it from disk again; unsaved changes are lost
SaveActions.Forget(coin);                    // remove one object's data on purpose
SaveActions.GameProfiles                     // every game profile, see below
  • SaveAll writes only the save files that changed.
  • Saving never erases objects that aren't loaded right now: the save system keeps the data it read and merges new captures into it.
  • When a saved object goes away, its latest values are captured first and written on the next save.
  • For UnityEvents and buttons, add MonoSaveActions to a GameObject. It has SaveAll() and SaveChosenFile(), which saves the save file picked from a dropdown in its inspector.
  • The config can save on quit and when the game loses focus (SaveOnQuit, SaveOnFocusLoss, both off by default).

Setting it up in a project

once per project

Nothing goes in a scene. Use Tools > External Project Tools > Save System > Create Config. It creates Assets/Resources/SaveSystemConfig.asset with the built-in save files and every library module's save file, and selects it. If a config already exists it only selects it.

The save system reads the config before the first scene loads and resets itself every time play mode starts, so it works with domain reload turned off.

Config fieldWhat it does
Use Debug PathSaves into DebugSaveFiles/ next to Assets/, so you can read the files while you work. Off: the player's save folder.
Startup PolicyAutoSetUp reopens the last game profile, or makes one, before the first scene. Manual waits for your save slot screen.
Default Game Profile NameThe name a new game profile gets, followed by its slot number: "Game Profile 2".
Game Profile Guid LengthHow many characters a game profile's folder name has.
Primary File ExtensionThe file type save files are written as.
Save On Quit, Save On Focus LossAutosave, both off by default.
Save Files Script PathWhere the editor writes SaveFiles.cs.
Save file listOne row per save file. See below.
With no config, the save system logs one error that names the asset and the menu item, and every call does nothing. The game keeps running.

Save files

once, then rarely

The config's save file list has one row per save file: a name, a save location and a Backup box. Three rows are built in and always exist: Global, GameProfile and Scene. Add a row for each extra file your game wants, such as Settings or Ghosts.

When the list changes, the editor writes SaveFiles.cs with one class per row. Scripts name those classes:

SaveFiles.cs, written by the editor
// SaveFiles.cs. Written by the editor. Don't edit; change the list in the config.
public static class SaveFiles
{
    public sealed class Global : ISaveFile { }
    public sealed class GameProfile : ISaveFile { }
    public sealed class Scene : ISaveFile { }
    public sealed class Settings : ISaveFile { }   // a row you added
}
  • Renaming a row keeps its old data readable: each row keeps the storage name it was first given.
  • The menu item Write SaveFiles.cs writes the file by hand, for example after a merge.
  • A library module ships its own save file class, marked with [SaveFileDefaults]. The editor adds its row ("Added by the Settings module") after each compile. You can still change its location and Backup box.
A module's own save file
[SaveFileDefaults("Settings", SaveLocation.Global)]
public sealed class SettingsSaveFile : ISaveFile { }

public class SettingsManager : MonoBehaviour, ISavable<SettingsDTO, SettingsSaveFile> { … }

Save locations

most games

Every save file lives in one of three save locations. A script never picks one; its save file's row does.

Save locationHoldsExample
GlobalData shared by every game profileVolume, key bindings
GameProfileOne playthroughCoins, inventory, quests
SceneOne scene inside one playthroughWhich chests are open in the Forest

Switching game profiles keeps Global data and swaps everything else. An object in an additively loaded scene saves into its own scene's file, not the active scene's.

Game profiles and save slots

most games

A game profile is one playthrough. You hold a GameProfile and call its methods; you never type its ID. Each one gets a slot number that never changes, so slot 2 stays slot 2 after slot 1 is deleted.

A save slot screen
GameProfile created = SaveActions.GameProfiles.CreateNew();   // "Game Profile 3"; not opened
GameProfile slot = SaveActions.GameProfiles.Get(2);           // by slot number
slot.Open();
SceneManager.LoadScene(SceneManager.GetActiveScene().name);   // reload after switching

foreach (GameProfile profile in SaveActions.GameProfiles.All)  // sorted by slot number
{
    Debug.Log($"{profile.SlotNumber} {profile.DisplayName} {profile.LastSaved} {profile.Playtime}");
}

slot.Rename("Hard mode run");
slot.Delete();                                // every file and backup of that game profile
GameProfile open = SaveActions.GameProfiles.Current;   // null when none is open
  • Every save updates the open game profile's game profile manifest: last saved time, last scene and playtime. profile.Custom holds game-specific details such as difficulty.
  • After opening a different game profile, reload your scenes. An object registered under the previous game profile never writes its values into the new one.
  • SaveActions.GameProfiles is never null. Without a config it is an empty list whose methods log one clear error.

Saving a plain C# class

often

Any object can save, not only MonoBehaviours. A plain class has no GameObject to carry a save ID, so it passes one when it registers.

A plain class
public class Inventory : ISavable<InventoryData>
{
    public List<string> Items { get; private set; }

    public Inventory()
    {
        Items = new List<string> { "Wooden Sword" };
        // Last line: saved items may be restored inside this call.
        SaveActions.Register(this, "player-inventory");
    }

    public InventoryData CaptureData() => new InventoryData { Items = new List<string>(Items) };
    public void RestoreData(InventoryData loadedData) => Items = new List<string>(loadedData.Items);
}

// Whoever owns it unregisters it when its scene ends; that captures the latest items.
void OnDestroy() => SaveActions.Unregister(inventory);

The save ID must be unique within its save file.

Load and save events

sometimes

SaveEventBus tells scripts when data is ready or written. Load events and OnGameProfileOpened are sticky: a script that subscribes after the event already happened is called right away, so it never matters whether it subscribed early or late.

SaveEventBus
SaveEventBus.OnLoadCompleted += file =>          // one save file restored; gives its class
{
    if (file == typeof(SaveFiles.Ghosts)) { ShowGhosts(); }
};
SaveEventBus.OnLoadAllCompleted += Refresh;       // Global data and the open game profile restored
SaveEventBus.OnGameProfileOpened += profile => { };
SaveEventBus.OnSaveCompleted += file => { };      // one save file written
SaveEventBus.OnSaveAllCompleted += ShowSavedIcon;
  • OnLoadCompleted comes after the file is read and every registered object in it is restored.
  • A Scene save file raises it once per scene, one frame after that scene's scripts start, so every object in the scene has its data first.
  • OnLoadAllCompleted fires each time a game profile opens. Closing the game profile clears the sticky state.
  • Each handler runs on its own. One that throws is logged with its name, and the others still run.

Forgetting saved data on purpose

sometimes

For a coin that was picked up and should stay gone. Pass the saved object itself: a plain class, a saved script, or its GameObject.

SaveActions.Forget
SaveActions.Forget(coin);      // stops tracking it and removes its data
Destroy(coin.gameObject);      // destroying it can't write it back now
SaveActions.SaveAll();         // the entry is gone from the file

Saving a ScriptableObject

sometimes

An asset registers itself like a plain class. A later step makes this automatic.

A saved asset
public class GameProgress : ScriptableObject, ISavable<GameProgressData>
{
    public int LevelsCompleted;

    void OnEnable()  => RegisterWithSaveSystem();
    void OnDisable() => SaveActions.Unregister(this);

    // In the Editor the asset can load before play mode starts the save system,
    // so a scene script calls this again in Awake. Registering twice is harmless.
    public void RegisterWithSaveSystem() => SaveActions.Register(this, "game-progress");

    public GameProgressData CaptureData() => new GameProgressData { LevelsCompleted = LevelsCompleted };
    public void RestoreData(GameProgressData loadedData) => LevelsCompleted = loadedData.LevelsCompleted;
}

Reading and writing a save file directly

editor tools, debug buttons

SaveStorage reads and writes a whole save file as JSON text in one line. The config says where the file lives and whether it keeps a backup, so nothing else is passed in. It works in play mode and in edit mode.

SaveStorage
SaveStorage.ReadText<SaveFiles.Settings>(out string json);                 // a Global file
SaveStorage.ReadText<SaveFiles.GameProfile>(out string json);              // the open game profile
SaveStorage.ReadText<SaveFiles.GameProfile>(profile, out string json);     // any game profile
SaveStorage.ReadText<SaveFiles.Scene>(profile, "Forest", out string json); // one scene
SaveStorage.WriteText<SaveFiles.Settings>(json);   // atomic; refuses text that isn't a save file
SaveStorage.Delete<SaveFiles.Settings>();
string path = SaveStorage.GetFilePath<SaveFiles.Settings>();   // for "Show in Explorer"
foreach (GameProfile profile in SaveStorage.GameProfiles) { }   // read from disk in edit mode
In play mode the running save system doesn't see a write. Call SaveActions.Reload<TFile>() after WriteText to restore the saved objects from the new text. The Settings module's debug toolbar is built on SaveStorage.

Editor tools

while debugging

Every tool is under Tools > External Project Tools > Save System.

Menu itemWhat it does

The config inspector shows the save file list one row per line. Built-in rows and rows added by a module say so, and come back if you remove them. A SaveFileReference field, such as the one on MonoSaveActions, shows a dropdown of the save files in the list.

What's on disk

while debugging

Each write goes to a temporary file first, is flushed to disk, then swapped in, so a crash during a write leaves the previous save intact. Backups live in their own folder that mirrors the main one, one backup per file.

The folder map
SaveFiles/                       (DebugSaveFiles/ next to Assets when Use Debug Path is on)
  Global/
    Settings.json
    SaveSystemMetaData.json      which game profile to reopen at startup
  GameProfiles/
    a1b2c3/
      GameProfileManifest.json   what a save slot screen shows
      GameProfile.json
      Scenes/
        Forest/
          Scene.json
  Backups/                       the same shape: the last good copy of each file
    Global/Settings.json
    GameProfiles/a1b2c3/GameProfile.json
    GameProfiles/a1b2c3/Scenes/Forest/Scene.json
One save file
{
  "FormatVersion": 2,
  "Version": "1.0",
  "Timestamp": "2026-11-13T04:12:08.0000000Z",
  "ProfileID": "a1b2c3",
  "FileName": "GameProfile",
  "Entries": {
    "5eecb91f-…/27062df3-…": {
      "name": "Assets/Scenes/Level.unity/Player/Health",
      "data": 40
    }
  }
}
  • Entries are matched by save ID only. name is there for a person reading the file.
  • A row with Backup ticked keeps the previous good copy. If its file is corrupt, the backup loads and a warning names the file.
  • A row with Backup unticked never falls back. A corrupt file logs one error that names it, and the objects keep their new-game values.
  • The game profile manifest and save system metadata are always backed up: losing a manifest would hide a whole game profile from the slot screen.
  • Deleting a game profile deletes its backups too.

Under the hood

library work and tests

Game code only touches the public classes above. The rest is internal, with one job per class. Storage passes keys such as GameProfiles/a1b2c3/GameProfile, never full paths.

PartIts one job
SaveStartupStarts the save system before the first scene and resets it whenever play mode starts or stops.
SaveSessionOne running save system: connects the registry, the loaded data and the game profiles, and applies the whichever-second rule.
SaveRegistryEvery registered saved object, by save file and save ID.
LoadedSaveDataThe data read from disk, kept in memory and merged with new captures.
SaveFileAddressesWhere a save file lives right now: its key and whether it keeps a backup.
SaveSessionEvents, LoadEventLogRead save files when a session, game profile or scene starts, and remember which have loaded for sticky events.
SaveFileLookupFinds a save file's row from its class.
SaveProfileManager, GameProfileListGame profiles by folder ID, and the handles game code holds.
SaveFileStoreWrites with an optional backup, and reads with a fallback to it.
SaveFileAccessWhat SaveStorage uses: the running session's parts, or parts built from the config in edit mode.
SavePathGeneratorBuilds every key in one place, so saving and loading can't disagree.
DiskStorageService, MemoryStorageServiceStore text by key: as files on disk, or in a dictionary so tests never touch real save files.
UnitySceneInfo, SceneReadySignalTell the save system which scenes are loaded, and when a newly loaded scene is ready.

Unity versions

starting a project

The library is built and tested in Unity 7 and also targets Unity 6 (the package's minimum is 6000.0), so a Unity 6.7 LTS project can use it.

  • Where Unity 7 renamed an API, the code picks the right name with a version define. For example the searchable dropdown reads childList on Unity 7 and children on Unity 6.
  • The save system keeps no static caches of types or methods, and resets every static when play mode starts, as Unity 7 requires.
  • The tests run in the Unity 7 Lab. Run them once in a Unity 6.7 project before relying on it there.
