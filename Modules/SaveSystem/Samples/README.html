Save System Samples

Eight small scenes that teach the save system one step at a time. They ship with the Abstract Pixel Library package and are for learning in the Unity Editor only.

Where they are

The samples are part of the package, next to the save system's code. There is nothing to import. Install the package (see Get started), then in the Project window open Packages/Abstract Pixel Library/Modules/SaveSystem/Samples/.

Modules/SaveSystem/
  Runtime/   the save system       AbstractPixel.SaveSystem
  Editor/    its editor tools      AbstractPixel.SaveSystem.Editor
  Tests/     its tests
  Samples/   these samples         AbstractPixel.SaveSystem.Samples (Editor only)
    01 Save A Field/ ... 08 ScriptableObject/   a scene, Scripts/ and README.html each
    Shared/  scene loading and the build guard
    Tests/   one PlayMode test per sample      AbstractPixel.SaveSystem.Samples.Tests

Open a sample's scene and press Play. To change a sample, copy its folder into Assets/ first. A package installed from git is read-only.

Each sample's first step is a scene button showing its Unity path. Click it with the Editor open to ping that scene in its Project window; no setup needed. With Unity closed, it copies the path for you to paste in, or opens File Explorer there if you've run assets/tools/register-scene-button.ps1 once (optional, Windows only).

Before any sample

  • Make a save system config once: Tools > External Project Tools > Save System > Create Config.
  • Every sample uses the built-in save files, so you don't add anything to the config.
  • You don't add the scenes to the build's scene list. The samples load their scenes in the Editor by themselves.

Editor only, never in a build

All sample scripts are in one assembly, AbstractPixel.SaveSystem.Samples, that compiles only in the Editor (its UNITY_EDITOR define constraint). Nothing in your game can reference it. If a sample scene, or any scene that uses a sample script, ends up in a player build, the build stops and names the scene.

The samples

Level 0 needs no code, level 1 is daily code, level 2 is choices, level 3 is full control. Most games only need levels 0 to 2.

SampleLevelShows
01 Save A Field1daily codeThe daily way to save: [Save] on a field of a MonoBehaviour, and on a plain C# class that calls SaveActions.Register(this).
02 Buttons With No Code0no codeA level saved with no code: Save Transform, Save Active State and Save Destroyed components, and uGUI buttons wired to Mono Save Actions.
03 Save Slots And Continue2choicesA save slot screen: create, open, list and delete game profiles by slot number, plus a Continue button.
04 Pick A Save File2choicesISaveIn<TFile> puts data in a Global, GameProfile or Scene file; Save<TFile>(), Reload<TFile>() and a typed load listener.
05 Spawned Copies2choicesGoblins spawned from one prefab, each with its own save ID from SetSaveId. Defeated ones stay defeated.
06 Custom Data With ISavable3full controlA plain C# Inventory that moves its own data with ISavable<T>, for data that isn't plain fields.
07 Whole Files With SaveStorage3full controlA debug screen that reads, copies, pastes and deletes a whole save file as JSON text with SaveStorage.
08 ScriptableObject1daily codeA GameProgress ScriptableObject asset with [Save] fields that registers itself with the save system.

Tests

Each sample has a PlayMode test in Tests/, in the AbstractPixel.SaveSystem.Samples.Tests assembly. Run them from Window > General > Test Runner > PlayMode. They write to the save folder, like playing the samples does.
