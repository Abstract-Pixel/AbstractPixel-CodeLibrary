ISavable<TData> 3 full control

A saved object that hands its data to the save system and takes it back. With no save file class, its data lives in the GameProfile save file. Use ISavable<TData, TFile> to pick another file.

In code#

Use ISavable<TData> when your saved data isn't plain [Save] fields, for example a struct you build from several pieces of live state. Use ISavable<TData, TFile> to say what and where in one line.

See Saving complex data with ISavable for the full Inventory, Inventory 2, Inventory 3 walkthrough, including how several live instances of the same class get their own save IDs.

Members#

Methods

TData CaptureData()method Returns this object's current data, to be written to the save file.
Capture is reading the current data out of a saved object so it can be written to a save file. Called on every save that includes this object's save file.
void RestoreData(TData loadedData)method Puts loaded data back into this object.
Restore is putting saved data back into a saved object. It happens as soon as both the object and its data exist, whichever comes second — normally right after every Awake and before any Start, whether the data comes from a save file or from new-game values (this object's values when it first registers, before anything is restored; they're put back when a game profile with no data for this object opens).

If it goes wrong#

Show fixes
Two instances of the same class share one save ID
Later instances get "ClassName 2", "ClassName 3" automatically, in registration order. Give a custom save ID if that order can change between runs.
RestoreData throws
The save system logs it and keeps the previous saved data on disk untouched. Fix RestoreData, then reload.
