IOnRestored 1 daily code

Called on a saved object right after each restore: after Awake, when new-game values apply, and when a different game profile opens. Use it to refresh anything that read the data before it was restored.

In code#

Implement IOnRestored on any saved object (a MonoBehaviour, a plain class, or a ScriptableObject). There is nothing else to register: the save system finds it through the interface.

When it runs#

OnRestored() fires at the end of every restore path, both a restore from a save file and a restore of new-game values for a fresh game profile. The order on scene load is: Awake, then the restore and OnRestored(), then Start. See Save, restore and react to data.

An exception in OnRestored is caught and logged, not thrown. The save system logs the saved object's type and save ID, then keeps going: "OnRestored on <Type> (save ID '<id>') failed: <message> The restored data is kept." The field values your [Save] fields already hold are not rolled back, only your OnRestored code didn't finish running.

Members#

Methods

void OnRestored()method Runs right after this object's data is restored.
This call is the restored notice: every saved object that implements IOnRestored gets it after each restore, including a restore of new-game values. Takes no arguments and returns nothing. Read the [Save] fields or ISavable data you already have; don't write to them here.

If it goes wrong#

Show fixes
OnRestored never runs
The object has no saved data to restore yet (nothing was ever saved for it), or it has no [Save] field and no ISavable implementation, so the save system never tracks it.
A value read in Start is still the new-game value
Read it in OnRestored instead. Start can run before a load event, but OnRestored always runs before Start.
