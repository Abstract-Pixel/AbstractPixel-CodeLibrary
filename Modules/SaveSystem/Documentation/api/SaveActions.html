SaveActions 1 daily code

The one class game code calls to save and load. Register a saved object once, and it gets its data back as soon as both the object and its data exist, whichever comes second. Until the save system has started, every call is a safe no-op.

In code#

There is no Load call. A script gets its data when it registers, which for a [Save] field happens automatically through its Savable Bridge.

Members#

Properties

public static GameProfileList GameProfilesproperty Every game profile, plus CreateNew, Current and Get(slot). Never null.
Without a save system config it is an empty list whose methods log one clear error.

Methods

public static void Forget(object savedObject)method Makes one saved object's data go away on purpose, so it doesn't come back.
Pass the saved object itself: a plain class, a saved script, or its GameObject. Call it before Destroy. Forgetting a scene object writes a gone marker, so the object turns itself off the next time its scene loads; forgetting a spawned copy or a plain class removes its data outright. See Forgetting saved data for good.
public static void Reload<TFile>()method Reads one save file from disk again and restores every saved object in it, throwing away unsaved changes.
An overload takes a SaveFileReference instead of a type argument.
public static void Register(object savedObject)method Registers a plain class whose saved data is its [Save] fields.
Its save ID is its class name, unless SaveIdAttribute names one. Overloads take an ISavable<T> object, or an explicit save ID string. Call it last in the constructor, after new-game values are set.
public static void SaveAll()method Captures every registered object, then writes every save file that changed.
public static void Save<TFile>()method Like SaveAll, for one save file only.
An overload takes a SaveFileReference instead of a type argument.
public static void Unregister(object savedObject)method Captures the object's current data, then stops tracking it.
Its data is still written on the next save.

If it goes wrong#

Show fixes
Every call silently does nothing
There's no save system config. Run Tools > External Project Tools > Save System > Create Config.
Two live instances of the same plain class swap data
Their registration order changed between runs. Give each a custom save ID instead of relying on the automatic "ClassName 2", "ClassName 3" numbering.
