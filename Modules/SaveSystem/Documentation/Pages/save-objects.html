Save plain classes, ScriptableObjects and spawned copies 1 daily code

A plain class, a ScriptableObject, and a spawned copy each save with one line beyond [Save].

Save a plain C# class#

Try it in the sample
Open sample 01: Save A Field →

Sample 01 · Save A Field

  1. Open the Save A Field scene and press Play.
  2. Press Find an item a few times, then Save and Reload scene.

Any class can save. It registers itself, and needs no save ID of its own.

Register on the last line, because saved data may arrive inside that call. The owner unregisters it when it's done, which captures the latest values for the next save:

void OnDestroy() => SaveActions.Unregister(backpack);

The class name is the save ID. A second live instance gets "Inventory 2", then "Inventory 3", in the order they register; see Saving complex data with ISavable for an example. Renaming the class would change its save ID, so put [SaveId("Backpack")] on it first and old saves keep their data.

Two live objects with the same save ID in one save file would overwrite each other. The save system refuses to register the second one and names both in the Console. Give one a different save ID, or, for a GameObject, remove its Savable Bridge and add it again for a new ID.
If it goes wrong
"can't register... another object already uses save ID" in the Console
Two live objects share a save ID. Pass a custom ID to Register, or fix the duplicate Savable Bridge.
Data isn't there after Register
Register runs last in the constructor on purpose. Read saved values after it returns, not before.

Save a ScriptableObject#

Try it in the sample
Open sample 08: ScriptableObject →

Sample 08 · ScriptableObject

  1. Open the ScriptableObject scene and press Play.
  2. Complete a level, then Save and Reload scene.

An asset registers itself, like a plain class, from its own OnEnable.

In the editor, Unity can load the asset before play mode starts the save system, so that first OnEnable call does nothing. A scene script calls RegisterWithSaveSystem() again in its own Awake to cover that; registering twice with the same ID is harmless.

Open sample 05: Spawned Copies →

Sample 05 · Spawned Copies

  1. Open the Spawned Copies scene and press Play.
  2. Defeat a goblin, then Save and Reload scene.

Every copy of a prefab starts with the same save ID, so give each spawned copy its own right after Instantiate.

The ID must be the same every time the game runs, which is why it comes from the spawn point's name instead of a random number. SetSaveId restores the copy's saved data inside that call, right after Instantiate and before its own Start.

A copy spawned with no SetSaveId isn't saved and logs one warning naming it.

SaveActions.Forget on a spawned copy removes its data outright, unlike a scene object's gone marker; see Forgetting saved data for good.
