React to loads and saves 2 choices

SaveEventBus tells scripts when data has loaded or saved. A load event is sticky: a script that subscribes after it already happened is called right away.

A typed load listener on the Scene file counts each scene's load, sticky across the trip.

Hear one save file load#

AddLoadListener<TFile> calls handler every time that save file's load event fires: once per scene for a Scene file, otherwise once. A Scene file raises its load event one frame after that scene's scripts start.

Hear everything load#

OnLoadCompleted gives the save file's class for code that wants every file, typed or not. OnLoadAllCompleted runs each time a game profile opens, once global data and that game profile are fully restored.

Hear saves and failures#

OnSaveCompleted means the file is on disk. A write that fails raises OnSaveFailed with a reason instead, so a "Saved" message never shows for a lost save. OnSaveAllCompleted always fires once, at the end of SaveAll.

If one handler throws, the others still run. The save system catches the exception, logs which handler and event, and keeps calling the rest.
If it goes wrong
"Saved" shows, but the file didn't change
A failed write can't raise OnSaveCompleted; it raises OnSaveFailed instead. Listen for that too.
A load listener never fires
